# Security policy

Report suspected vulnerabilities privately via GitHub's private vulnerability reporting (Security → Report a vulnerability, once enabled on the repository). If that channel is unavailable, ask the maintainer for a private reporting channel without posting details publicly. Include a minimal synthetic reproduction and affected version. Do not upload credentials, real transcript exports, unredacted logs or audio.

The project is pre-1.0; report issues against the current release or current main branch. Do not rely on a guaranteed fix timeline. Security-sensitive changes require review of data handling, macOS permissions, signing and dependency integrity.
